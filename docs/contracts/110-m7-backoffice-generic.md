## 1. Four-eyes on guarded changes (all tenants)
Guarded changes (plan §17): raising approval thresholds / auto caps, removing or weakening refuse/never-auto policy rules, reclassifying a write/destructive tool as read or untrusted_text as trusted, binding `auto` on a write tool, enabling an external-egress connector, adding a first-party trust level, changing the active embedding profile, deleting a connector or KB. Instead of 403, such a PUT/PATCH creates a **change request** `admin_change_request(id, tenant, kind, target, payload, diff, requested_by, status: pending|approved|rejected|applied|expired, approver, decided_at, expires_at (72 h))`; a *different* tenant-admin (or a platform-admin) approves via `POST /api/admin/change-requests/{id}/approve|reject {reason}`; approval applies the change atomically (re-validated against the current state; 409 if the base version moved). Self-approval impossible; platform-admins may co-sign any tenant. Everything audited. UI: "Pending changes" queue + inline "Requires a second admin" banners.

## 2. Tenants & users (platform-admin; tenant-admin for own tenant)
`GET /api/admin/users` (users holding the tenant attribute, with realm roles) · `POST /api/admin/users {username, email, name, roles[]}` (Keycloak admin API, realm keelson: create user with the tenant attribute, set a temporary password + required action UPDATE_PASSWORD; never return the password — show a one-time link/instruction) · `PATCH /api/admin/users/{id} {roles[], enabled}` (only product roles; tenant-admin cannot grant platform-admin) · `DELETE` (disable). Tenants page (platform-admin): list, create from pack (exists), suspend (blocks logins via attribute + API guard).

## 4. Connectors: Tier-A generic proof (foreign ERP)
- **Read mapping** (`connector_mapping` kind=read, versioned, YAML/JSON edited in the admin): per scn entity `{entity, source:{tool, args (JSON template), page_param, page_size, items_path (JSONPath-lite), cursor_path|null, max_pages}, fields:{scn_column: expression}}` where expressions are a small safe language (`$.field`, string concat, `int()`, `date()`, constant, lookup table) — **no eval**. Checks: required columns present, counts, FK sanity. 
- **Crawl sync** (tier A): `core/scn_crawl.py` pages through the mapped read tools with the connector's reader auth (static_header for /mcp-lite), via the egress proxy, maps rows to scn/1.0, loads them like a snapshot with `consistency: crawled` and `as_of_range {from, to}`; plans built on a crawled snapshot are labelled **advisory** ("Data gathered by paging, not a consistent snapshot") in blocks and the narrative.
- **Action mapping** (kind=action): per canonical op `{op, tool, args (template with {{payload.*}}, {{target_ref}}, {{expected_version}}), idempotency: enforced|best_effort|none, request_id_arg|null, readback:{tool, args, match}}`; admin **dry-run**: renders the tool call for a sample action without executing (and runs the read-back query) so admins can verify. Unmapped ops → guided steps (§2 of 95) with generated instructions.
- **Per-op commit** for tier-A connectors: commit ledger states attempted|succeeded|in_doubt|failed; `best_effort`/`none` ops get a read-back before any retry; `none` ops are never auto-retried; atomic groups on a tier-A connector are refused for bulk apply (guide instead) unless every member op is idempotent-enforced; policy as usual (human approval).
- **Generic proof scenario**: tenant `northwind-test` (pack `blank` + connector `merxa-lite` registered via the wizard with a Merxa API key): read mapping for sku/style/location(dc, store cluster derivation)/po_line/inventory_position/demand_forecast/allocation/transfer_order_line via `list_items`, action mapping for `transfer_order.create` → `create_transfer_order` and `allocation.set_qty` → `update_item(type=allocation, key, fields_json={qty}, expected_version)`; everything else guided. Running the trim-delay story for northwind-test yields advisory options, bulk-applies the mapped transfer lines per-op with approval, and guides the rest — end to end.
- Pack `foreign-erp-lite` (data/packs) with the mapping files so the proof is reproducible.
