# 100 · M6 signals — Signal Hub (GDACS, USGS, trade-press RSS, connector events), exposure, alerts inbox, demo packs, Act 1

Plan §10/§15/§18 (Act 1). Models: Flash/Flash-Lite only. Gemini credits may be depleted: everything must work and be tested without live model calls; only *news extraction* needs an LLM, and demo packs ship pre-baked extractions.

## 1. Service `signal-hub` (new; Python 3.14, FastAPI + FastMCP 4; own uv project; image used by two compose services)
- `signal-hub-api` (port 8300, networks `app` + `ai` (LiteLLM for news extraction)): REST + MCP, internal only (no Caddy route). `signal-hub-poller` (same image, `python -m signal_hub.poller`): adapters on schedules; leader via Postgres advisory lock; outbound HTTP **only via the egress proxy** (`HTTP(S)_PROXY=http://egress:3128`).
- Storage: database **`signals`** in pg-core (PostGIS) with role `signals`; created idempotently by `python -m signal_hub.bootstrap` (one-shot compose service using the pg-core superuser from `.env` only for CREATE ROLE/DATABASE/EXTENSION, then numbered migrations as role `signals`). Tenant rows (exposures, alerts, tenant networks, tenant-origin signals) are RLS-FORCE scoped by `app.tenant_id`; global feed signals/events have `tenant NULL` and are readable by all tenants.
- Auth: every REST/MCP call needs an engine **service JWT** (HS256, secret `SIGNAL_HUB_SHARED_SECRET`, `iss keelson-engine`, `aud signal-hub`, `tenant`, short exp); the tenant claim scopes all tenant data.

## 2. Model (Pydantic in `packages/contracts-py` `keelson_contracts.signals`)
- `DisruptionSignal {id (uuid5 of connector+native id/canonical url+version), tenant|null, origin: feed|news|connected_system|chat|demo, kind: natural_hazard|weather|geopolitical|labor|logistics|regulatory|cyber|supplier|demand|hypothetical, subtype (e.g. tropical_cyclone, earthquake, flood, port_closure, strike, supplier_delay), title, summary|null, raw_text|null (news: headline+snippet only), geometry (GeoJSON, float WGS84 — stored as PostGIS geography), location_refs [UNLOCODE:…, ISO3166:…, CHOKEPOINT:…, SUPPLIER:…], starts_at, ends_at|null, observed_at, expires_at|null, severity_bp (0–10000, formula), severity_native {scheme, …}, confidence_bp (formula: authority × corroboration × recency), provenance: fact|inference|simulated, extracted_by|null, source {connector_id, name, url|null, license, authority_bp, retrieved_at, native_id}, event_id|null, version, supersedes|null}`.
- `DisruptionEvent` (cluster): `{id, tenant|null, kind, subtype, title, summary, anchor_signal_id|null, member_signal_ids, geometry (merged), window, severity_bp, confidence_bp, status: candidate|confirmed|monitoring|resolved, taxonomy_key (one of the M4 event types, mapped deterministically), updated_at}`.
- `Exposure {event_id, tenant, node_type: supplier|factory|port|dc|store|lane, node_code, method: intersects|dwithin_km|lane_crosses|entity_match, distance_km|null, weight_bp}` + `ExposureSummary {nodes_by_type, open_po_lines|null, units_inbound|null}` (counts from the tenant network snapshot; no LLM numbers).
- `Alert {id, tenant, event_id, status: new|seen|snoozed|dismissed|opened|resolved, severity: low|medium|high|critical, title, why (deterministic sentence from rule + exposure), exposure_summary, first_raised_at, updated_at, case_id|null, simulated: bool}` + `AlertRule {id, when: {min_severity_bp, kinds[], min_confidence_bp, min_exposed_nodes, node_types[]}, action: alert|alert_and_draft_case|ignore, hysteresis_bp}`.
- Scenario packs: `ScenarioPack {id, title, description, start_at, steps:[{t_offset_s, adapter: gdacs|usgs|rss|merxa_inject|chat_hint, payload, note}]}`.

## 3. Adapters (deterministic parsing → `fact`; news → quarantined extraction → `inference`)
- **GDACS**: `https://www.gdacs.org/gdacsapi/api/events/geteventlist/SEARCH?eventlist=TC;EQ;FL&fromdate=…&todate=…&alertlevel=orange;red` (+ `geteventdata` for geometry); GeoJSON with `alertlevel`, `alertscore`, `severitydata`, `affectedcountries`, episode ids → TC/EQ/FL signals; licence CC BY 4.0 (attribution shown in UI). Cadence 10 min.
- **USGS**: `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/4.5_day.geojson` (mag, alert, tsunami, sig); public domain; 5 min.
- **RSS (one trade-press feed by default, configurable list)**: e.g. `https://theloadstar.com/feed/` — store headline, snippet (≤ 300 chars), link only; extraction via LiteLLM `extract-fast` behind a `guard-default` screen (no tools, strict schema → `{kind, subtype, places[], companies[], ports[], chokepoints[], dates_text[], injection_suspected}`); geocode via gazetteer; provenance `inference`; 15 min. If the LLM is unavailable (402/timeout) the item is stored `pending_extraction` and retried later — never fabricated.
- **Connector events** (tenant-scoped): engine forwards Merxa webhooks (`supplier_message.received`, `lane.capacity_changed`, `sailing.updated`, `po_line.updated`) to `POST /v1/ingest/connector-event` (service JWT, tenant from token) → structured fields = fact, free text → quarantine extraction (inference); `origin: connected_system`.
- All HTTP: ETag/If-Modified-Since, per-source rate limit, persisted cursors, timeouts, egress proxy.
- **M8 feeds** (NHC, Copernicus EMS, OFAC SDN, GDELT 2.0 events, MeteoAlarm; source registry, tenant opt-in): `124-m8-signal-feeds.md`.

## 4. Gazetteer, dedupe, clustering (v1)
Gazetteer from repo data: `data/geo/chokepoints.json`, `regions.json`, `country_centroids.json`, plus new `data/geo/ports.json` (UN/LOCODE subset with coordinates for all Merxa/Keelson ports and major Asia/Europe ports). Dedupe by native id / canonical URL (version bump on update). Clustering v1: authoritative feed signals (GDACS/USGS) are **anchors**; news/connector signals attach to an open event when kind is compatible, time overlaps ±72 h, and geometry is within 300 km or a location_ref matches; otherwise they form their own candidate event. Severity/confidence by formula; an LLM may only write an event title/summary for news-only events (inference) — optional, skipped when unavailable.

## 5. Tenant network + exposure + alerts
- Engine pushes each tenant's network after every scn sync: `PUT /v1/tenants/{tenant}/network` with nodes `{type, code, name, lat, lon}` (suppliers, factories, ports, DCs, stores aggregated to clusters) and lanes `{code, mode, path: [[lon,lat]…]}` (from `data/geo/sea_routes.json` paths). Stored as PostGIS geography.
- Exposure per (event, tenant): nodes within the event geometry (`ST_Intersects`) or within a kind-specific radius (`ST_DWithin`: TC 300 km of track/cone, EQ by magnitude (≥ 6.5 → 250 km, else 100 km), FL 50 km, port events: the port node), lanes whose path crosses the geometry (`lane_crosses`), and `entity_match` for connector events (supplier/port codes).
- Alert rules (per tenant; defaults in the pack/spec): alert when severity ≥ 4000 bp **and** ≥ 1 exposed node; `alert_and_draft_case` for severity ≥ 7000 bp with an exposed supplier/factory/port; hysteresis: an update edits the alert and only re-notifies when severity rises ≥ 1000 bp; alerts auto-resolve when the event resolves/expires. **Never** auto-commit anything.
- REST (service JWT): `GET /v1/alerts?status=&limit=` (tenant), `GET /v1/alerts/{id}` (with event, member signals + attribution, exposures), `POST /v1/alerts/{id}/status {status}`; `GET /v1/events/{id}`; `POST /v1/tenants/{tenant}/network`.
- MCP tools (read-only, for the `external_intel` specialist): `search_signals(query?, kinds?, since?, near_node?)`, `get_event(event_id)`, `hazards_near_node(node_type, node_code, radius_km?)`, `assess_exposure(event_id)` — structured outputs; any `raw_text` is marked untrusted (tool classified `untrusted_text` → quarantine in the engine).

## 6. Engine integration
- Platform: push tenant network after sync; forward connector webhooks to the hub; **Alerts API** for the web: `GET /api/alerts`, `GET /api/alerts/{id}`, `POST /api/alerts/{id}/open-case` (creates a case + enqueues a `signal` run `{event_id, alert_id}`; idempotent: one case per alert), `POST /api/alerts/{id}/dismiss|snooze|seen`; alert count for the Home pill; a tenant-level SSE channel `GET /api/alerts/events` (or reuse case SSE infra) pushing `CUSTOM sc.alert.*` events; `alert_and_draft_case` → the engine opens the case automatically (still waits at the approach card). Signal Hub registered as an internal first-party connector (auth kind `service_jwt`), its MCP tools approved read-only; `get_event`/`search_signals` text fields classified `untrusted_text`.
- Runtime: `signal` runs with `{event_id}` → deterministic `frame_from_event`: event → taxonomy key (TC/storm → `NAT.storm`, EQ → `NAT.storm`-like `NAT.earthquake` (add to taxonomy), FL → `NAT.flood`, port_closure → `LOG.port_closure`, strike → `LOG.strike`, supplier_delay → `SUP.delay`), exposed nodes → matched entities (fact), window/duration from the event or taxonomy priors (assumption), news-derived fields → inference (unconfirmed) → planner → approach card ("Opened from alert …") → investigation including the new **`external_intel`** specialist (Signal Hub MCP via quarantine) → options. Policy rule 2 already forbids auto-approval for non-chat origins.
- Add `NAT.earthquake` to the taxonomy (contracts EVENT_TYPE_KEYS + events.yaml) with capacity_scale on ports/factories within the footprint.
