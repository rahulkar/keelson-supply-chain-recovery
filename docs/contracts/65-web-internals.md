pnpm workspace root = repo root (`pnpm-workspace.yaml`): `apps/keelson-web`, `packages/{tokens-keelson,ui-keelson,viz,contracts-ts}`. `apps/merxa-web` is **outside** the workspace (own `package.json` + lockfile; never imports `@keelson/*`).

## Ownership
| Owner | Paths | Package names |
|---|---|---|

## W1 app (Next.js 16.3, App Router, `output: 'standalone'`, `reactCompiler: true`)
- Routes: `/` Home (greeting, Composer, 3–4 suggestion chips, "N new alerts" pill (static 0 in M1)), `/cases/[id]` thread, `/cases` history drawer/list, `/alerts` (M1 placeholder), `/admin` (M1 placeholder, role-gated), `/dev/blocks` (DEMO only).
- Auth: middleware/`proxy.ts` checks `keelson_session` cookie presence; unauthenticated → `/api/auth/login?next=`. Header shows user + **persona switcher** (DEMO: `GET /api/demo/personas`, `POST /api/demo/login-as`).
- API client: same-origin `fetch('/api/…', {credentials:'include', headers:{'X-CSRF-Token': csrf}})`; `Idempotency-Key` (uuid) on POST messages/actions.
- Stream: `useCaseStream(caseId)` — `EventSource('/api/cases/{id}/events')` (auto-reconnect with Last-Event-ID), parse with `parseAgUiEvent`, reduce into: `stages`, `agents/activities` (from SUBAGENT_*, TOOL_CALL_* using `metadata.sc.label`), `reasoning` (append deltas, replace on aggregate), `blocks` (ACTIVITY_SNAPSHOT sc.render by block id), `messages` (TEXT_MESSAGE_*), `interrupts` (RUN_FINISHED outcome interrupt), `runStatus`. Dedupe by seq.
- Thread layout: user bubble → ThinkingTimeline (collapsed) → assistant narrative → inline blocks (placement inline) → follow-up chips. Canvas side panel (55% ≥1280px, sheet below) shows canvas blocks with tabs Result / Evidence / Trace (Trace: list of agents & steps for M1). Auto-open canvas on first heavy result.
- Decisions: `POST /api/interrupts/{id}/decision`; case actions `POST /api/cases/{id}/actions`; approval 412 `connect_required` → navigate to `connect_url` (return_to current case).
- Dockerfile: build context repo root; installs workspace deps, builds `@keelson/web` standalone.

### W1 app (updated M4, 2026-10-07)
- **Decisions** (`useCaseActions.decisionBody`): sends `decision`, `plan_version`, `change_set_hash`, `edits` (M1 text or the M4 typed list) and `removed_checks`. A malformed typed list is never posted: `InvalidDecisionError` is raised and a toast explains it. **Known gap:** engine-api still accepts only text `edits`, so a typed Edit is answered with 422 `invalid_request` (see `30` M4 REST). The free-text Edit of M1 cards works.
- **Case actions** (`actionBody`): `{type, option_id, plan_version, assumption_keys}` for `confirm_assumptions`, with 1–50 keys; an empty list is refused client-side. The keys are part of the idempotency signature. `promote` posts `{type, option_id, plan_version}`. Note: the engine API caps `assumption_keys` at 32 (the run contract allows 50).
- **Follow-ups** are ordinary chat messages; the engine's `followup_delta` classifies them.
  - On an option turn, the chips ask about the first real alternative ("Why not …?") and offer a re-simulation with the case's own time value (`followUpContext`: "What if the delay doubles?" / "What if the duration doubles?").
  - A follow-up's `what_changed` shows above the streamed narrative (`whatChangedOf`).
- **Agents.** Display names come from the engine (`AGENT_DISPLAY_NAMES`: adds `planner` "Planner" and `playbook` "Playbook analyst"). One-line role descriptions live in `src/lib/agents.ts` (`AGENT_ROLE_DESCRIPTIONS`); custom specialists get none.
- **Admin › Agents** (`AgentsPage.tsx`, `lib/admin/spec.ts`): `MODEL_ROLES` / `PROMPT_ROLES` add `planner` and `critic` in pipeline order, so both get a card with an alias select, a prompt addendum (≤ 4,000 chars, counter and framing preview) and their own placeholder. `criticProblem()` blocks saving when the critic's effective alias equals the planner's (the engine's `_independent_critic` rule); a role missing from an older spec uses the catalog's alias (`catalog()` normalises the stored spec, so pre-M4 versions show the defaults). The catalog role schema accepts `prompt_role`, `prompt` and `uses_tools` (the engine catalog's specialists also list their `quarantined` sources). There is no editor for `quarantined` / `kb_ids` yet; a 422 `quarantine_source_invalid` (pack, API or restore) shows through `adminError(message)`.
- **Admin › Knowledge** (`/admin/knowledge`, engine `routes_admin_kb.py`, `90` §7):
  - knowledge bases (list and create; `409 name_taken`);
  - documents of the selected base (status processing / ready / failed with the reason; re-read every 3 s while processing);
  - upload by drag and drop or file chooser: one `.md`/`.txt`/`.pdf` ≤ 5 MB, checked before sending, multipart through `ApiClient` `form` (CSRF applies), `duplicate: true` → "Already in …";
  - delete with confirmation;
  - the embedding profile and **Re-embed documents** (`scope: "tenant"`); platform admins also get **New profile** (`scope: "platform"`, `alias`, `dims ≤ 4000`).
